The problem

Touching a keyboard is not always an option.

Laboratories, clean rooms, clinics, workshops, kitchens, kitchens-of-code with a very full desk — the places where a mouse and keyboard are awkward, unhygienic or simply out of reach. Existing gesture tools are either expensive, cloud-dependent, or limited to moving a cursor around.

Reach

Camera-only control: point to move, pinch to click, hold to drag, scroll and zoom with finger counts.

Express

A radial command wheel, two-hand chords and a floating keyboard turn gestures into intent, not just motion.

Trust

Allow-listed actions only, test mode before live input, emergency stop, and a strictly local video pipeline.

Honest attribution

AIRDESK is an evolution of Gestura, not a rewrite.

The foundation is the open-source Gestura project by Raphzaf, licensed GPL-3.0-or-later. Its tracking pipeline, gesture engine, controller layer and PySide6 interface were studied, kept and extended — never replaced with untested alternatives. The upstream LICENSE and copyright notices remain in place, and this site separates inherited work from AIRDESK contributions on purpose.

Feature set

Four additions, one gesture vocabulary.

01

Air Command

A fist opens a radial menu; the right index finger sweeps the sectors; a pinch confirms; an open palm cancels. Every entry maps to a pre-declared action — browser, calculator, file manager, screenshot, keyboard, modes, media, pause. Gesture input can never compose a shell command.

02

Air Macros

Chain up to a dozen safe steps — open an allow-listed app, press a whitelisted shortcut, switch mode, raise the keyboard, change volume, advance slides — with per-step delays, reordering and a manual test run. Destructive macros can require an explicit confirmation.

03

Two-hand chords

The right hand keeps the cursor; the left hand becomes a modifier. Pose pairs such as fist + two fingers trigger a command once, with debouncing and a cooldown, and only while the wheel is closed so the two systems never fight.

04

Multi-monitor control

Displays are enumerated from the OS, one is selectable from the dashboard, and normalized hand coordinates map into that display's geometry — including negative origins. Switching displays glides the cursor in bounded steps instead of teleporting it.

Computer vision

One frame, five stages, no network hop.

Capture, landmark detection, feature extraction, gesture state machines and finally an allow-listed action. Each stage is a plain Python component with its own tests, which is why new features could be added without touching the detector.

  1. 01 · Capture

    OpenCV video source

    Webcam frames at the requested resolution and FPS, with MSMF / DirectShow / V4L2 backend selection.

  2. 02 · Perception

    MediaPipe landmarks

    21 hand landmarks per hand plus face landmarks, produced offline on the CPU.

  3. 03 · Features

    Normalized geometry

    Pose classification, pinch distance, handedness, confidence and smoothing — resolution independent.

  4. 04 · Intent

    Gesture state machines

    Debounce, cooldown, chord matching and the radial wheel selector turn poses into a single intent.

  5. 05 · Action

    Allow-list + safety

    Registry lookup, safety manager, worker thread, visible feedback. Test mode simulates instead of injecting.

Interaction design

A wheel you can learn in ten seconds.

The wheel is a pure state machine, not a pile of timers: hold to open, sweep to select, pinch to confirm, open palm to cancel, with a dead zone in the middle so a resting hand never fires. Confirmation needs a fresh pinch, so a held pinch cannot trigger twice.

  1. Hold the left fistOpens after a configurable hold; a progress arc shows the wait.
  2. Point with the right handTwelve fixed sectors, sector 0 at twelve o'clock, clockwise.
  3. Pinch to confirmSelected sector closes the wheel and runs one allow-listed command.
  4. Open palm to cancelCloses with no action, after a short hold that avoids accidental cancels.

Also included

Floating virtual keyboard

A translucent QWERTY / AZERTY board that hovers over other windows. The hand cursor selects keys, presses are debounced, and nothing is sent while test mode or the emergency stop is active. Layout and scale are configurable.

Privacy

Your camera never leaves the machine

Frames are consumed in memory by a local worker, rendered to a preview and discarded. No recording, no upload, no analytics, no accounts. The only files written are your settings, your macros and screenshots you explicitly trigger.

Platform support

Windows today, Kali Linux as the deployment target.

Development and interactive testing happen on Windows 11. Kali Linux is the target machine, so the code prefers X11 tools, detects Wayland and reports what it cannot do instead of pretending. Anything below marked “untested” has not yet been run on that operating system.

Technical honesty

What this build does not claim.

Known limitations

  • Hand tracking needs reasonable, even lighting and roughly 40–90 cm of distance.
  • Gesture recognition is rule-based geometry, not a trained classifier.
  • Wayland compositors block synthetic input; X11 (or a X11 session) is required for control.
  • Kali behaviour is implemented and unit-tested, but not yet exercised on Kali hardware.
  • Macro steps stay inside fixed allow-lists — there is no terminal action, by design.

How changes were verified

  • Baseline of the unmodified upstream: full test suite + a scripted smoke run.
  • After every change: the same suite, now including tests for the new subsystems.
  • UI checked by rendering real Qt windows, not by assuming the stylesheet applied.
  • Real-desktop input deliberately disabled while verifying.
  • Anything unverified is labelled unverified rather than described as working.
